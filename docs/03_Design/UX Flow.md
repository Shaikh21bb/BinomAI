## 1. Обзор пользовательских потоков

BINOM AI имеет **5 основных пользовательских потоков**:

| # | Поток | Описание |
|---|-------|----------|
| F1 | Регистрация и онбординг | Новый пользователь → первый проект |

## 3. F2: Основной рабочий поток (Core Flow)

### 3.1 Полная схема (Happy Path)

```
[Dashboard]
    │
    ├── Нажать "+ Новый тендер"
    │
    ▼
[Создать проект — Dialog]
    │ Ввод: Название, Заказчик (опц.), Дедлайн (опц.)
    │ [Создать]
    │
    ▼
[POST /projects] → Проект создан (status: draft)
    │
    ▼
┌─────────────────────────────────────────────────────────┐
│             PROJECT WORKSPACE                           │
│  Tabs: [📄 ТЗ] [🤖 Анализ] [💬 Диалог] [📝 Доки] [📥]  │
└─────────────────────────────────────────────────────────┘
    │
    ▼ (Tab: ТЗ)

─── ШАГИ ────────────────────────────────────────────────
    
STEP 1: ЗАГРУЗКА ТЗ
    │
    ├── Drag & Drop или клик "Загрузить"
    ├── Выбор файла (PDF/DOCX, < 50 МБ)
    │
    ├── ❌ Неверный тип → Error toast + инструкция
    ├── ❌ Слишком большой → Error toast + инструкция
    └── ✅ Файл принят
    │
    ▼
[POST /projects/{id}/documents]
    │ Response: task_id + status: "processing"
    │
    ▼
[WebSocket слушает task updates]
    │
    ├── WS: task:started → "Документ загружается..."
    ├── WS: task:progress (65%) → "Извлечение текста..."
    └── WS: task:completed → Файл готов
    │
    ▼ Автоматически (без клика)

STEP 2: AI АНАЛИЗ (автоматически после загрузки)
    │
    [Статус проекта: "analyzing"]
    │
    ├── Loading state: AI Spinner + "Анализирую ТЗ..."
    │   [Прогресс-бар с shimmer эффектом]
    │
    ├── ❌ AI Error →
    │   │ Toast: "Ошибка AI. Попробуйте снова."
    │   │ Кнопка "Повторить анализ"
    │   └── POST /analysis/retry
    │
    └── ✅ Анализ завершён (≈ 15-30 сек)
    │
    ▼
[GET /projects/{id}/analysis → отображение AnalysisPanel]
    │
    │ Пользователь изучает:
    │  - Резюме ТЗ
    │  - Требования по категориям
    │  - Риски (Risk Radar)
    │  - Gap Analysis
    │
    ▼ Нажать "Перейти к диалогу →"

STEP 3: AI ДИАЛОГ (Tab: Диалог)
    │
    [Статус проекта: "clarifying"]
    │
    ├── AI автоматически задаёт первый вопрос
    │
    ├── Пользователь читает → вводит ответ → Send
    │
    ├── AI обрабатывает → задаёт следующий вопрос
    │
    ├── [Repeat для каждого вопроса...]
    │
    ├── Пользователь может задавать собственные вопросы
    │   "Что имеется в виду под пунктом 3.4?"
    │
    └── ✅ AI: "Достаточно данных! Можно генерировать документы."
        [Кнопка "Перейти к генерации →" активируется]
    │
    ▼

STEP 4: ГЕНЕРАЦИЯ ДОКУМЕНТОВ (Tab: Документы)
    │
    [Статус проекта: "generating"]
    │
    ├── Три карточки документов:
    │   [Коммерческое предложение] [Техническая спецификация] [Сопроводительное письмо]
    │
    ├── Нажать "Сгенерировать КП"
    │   │
    │   ├── POST /projects/{id}/generate { doc_type: "commercial_proposal" }
    │   ├── Loading: AI прогресс-бар ~45 сек
    │   └── ✅ КП готово
    │
    ├── Нажать "Сгенерировать ТС" → аналогично
    │
    ├── Нажать "Сгенерировать Письмо" → аналогично
    │
    └── Пользователь открывает документ в редакторе
        │
        ├── Читает, редактирует текст
        ├── Перегенерирует отдельные секции если нужно
        └── Оставляет оценку 👍 / 👎
    │
    ▼

STEP 5: ЭКСПОРТ (Tab: Экспорт)
    │
    ├── Кнопка "Скачать DOCX"
    │   │ POST /export { format: "docx" }
    │   │ ≈ 5-10 сек
    │   └── Браузер скачивает файл
    │
    └── Кнопка "Скачать PDF"
        │ POST /export { format: "pdf" }
        │ ≈ 5-10 сек
        └── Браузер скачивает файл
    │
    ▼
[Статус проекта: "done"]
    │
    ▼
[Опционально: пометить как "submitted" после подачи]
    │
    END ✅
```

## 4. F3: Управление проектами

### 4.1 Создание проекта

```
[Dashboard → кнопка "+ Новый тендер"]
    │
    ▼
[Модальное окно "Новый тендер"]
    │
    ├── Название: [обязательное поле]
    ├── Заказчик: [опциональное]
    ├── Дедлайн: [date picker, опциональное]
    ├── Заметки: [textarea, опциональное]
    │
    ├── [Создать] → POST /projects
    └── [Отмена] → закрыть модал
    │
    ▼ (при успехе)
Редирект → /projects/{id}/document
```

### 4.2 Изменение статуса проекта

```
[ProjectCard или ProjectWorkspace → клик на Status Badge]
    │
    ▼
[Dropdown меню статусов]
    │
    ├── Draft
    ├── In Progress  ← текущий
    ├── Review
    ├── Done
    ├── Submitted
    └── Archived
    │
    ├── Выбрать новый статус
    │
    ▼
[PUT /projects/{id} { status: "review" }]
    │
    └── Обновление Badge в реальном времени
```

### 4.3 Удаление проекта

```
[ProjectCard → контекстное меню [⋮] → "Удалить"]
    │
    ▼
[ConfirmDialog]
    │ "Вы уверены? Это действие нельзя отменить."
    │ "Будут удалены все данные: ТЗ, анализ, документы."
    │
    ├── [Отмена] → Закрыть диалог
    └── [Удалить навсегда] ← красная кнопка
        │
        ▼
    [DELETE /projects/{id}]
        │
        └── Toast: "Проект удалён"
        └── Редирект → Dashboard
```

### 4.4 Поиск и фильтрация

```
[Dashboard]
    │
    ├── SearchInput → фильтрация по названию (real-time, debounce 300ms)
    │
    ├── Filter: Статус [Все / Draft / Analyzing / Done / Submitted]
    │
    └── Sort: [Дата создания ↓] [Дедлайн ↑] [Название A-Z]
```

## 6. F5: Потоки ошибок

### 6.1 AI недоступен

```
[Пользователь загружает ТЗ]
    │
    ▼
[AI Analysis Task запущен]
    │
    ├── Celery → Gemini API → 503/timeout (первая попытка)
    ├── Автоматический retry → GPT-4o fallback
    │
    ├── ✅ GPT-4o ответил → анализ завершён (пользователь не знает о fallback)
    │
    └── ❌ Оба AI недоступны →
        WS: task:failed { error: "AI_UNAVAILABLE" }
        │
        ▼
    Toast: "AI-сервис временно недоступен. Попробуйте через 2 минуты."
    Кнопка "Повторить" → POST /analysis/retry
```

### 6.2 Загрузка неподдерживаемого файла

```
[Пользователь перетаскивает .xlsx файл]
    │
    ▼
[Frontend валидация (до загрузки)]
    │
    └── ❌ Неверный тип → 
        Inline error под зоной загрузки:
        "Поддерживаются только PDF и DOCX файлы"
        Зона остаётся активной для повторной попытки
```

### 6.3 Ошибка генерации документа

```
[Генерация КП запущена]
    │
    ▼
[AI Generation Task]
    │
    ├── ❌ JSON validation error (AI вернул неверную структуру)
    │   → Автоматический retry (до 3 попыток)
    │   → При 3-й неудаче → task:failed
    │
    └── ❌ Failed after retries →
        WS: task:failed
        │
        ▼
    Toast: "Ошибка генерации. Попробуйте снова."
    Кнопка "Повторить" возле карточки документа
```

### 6.4 Истёкшая сессия

```
[Пользователь пытается выполнить действие]
    │
    ├── Frontend: access_token истёк
    │
    ├── Автоматический refresh → POST /auth/refresh
    │   ├── ✅ Новый токен → действие выполняется прозрачно
    │   └── ❌ Refresh тоже истёк →
    │       │
    │       ▼
    │   Toast: "Сессия истекла. Войдите снова."
    │   Редирект → /login
    │   После логина → редирект обратно на страницу
```

## 7. Навигационные паттерны

### 7.1 Главная навигация (Sidebar)

```
Уровень 1: Глобальные разделы
  → Dashboard (список проектов)
  → Settings

Уровень 2: Внутри проекта
  → ТЗ (Document)
  → Анализ (Analysis)
  → Диалог (Chat)
  → Документы (Generate)
  → Экспорт (Export)
```

### 7.2 Breadcrumb

```
Все проекты > Тендер НПЗ Шымкент > Анализ
```

### 7.3 Tab navigation (внутри проекта)

Горизонтальные табы с индикаторами:

```
[📄 ТЗ ✅] [🤖 Анализ ✅] [💬 Диалог 6/10] [📝 Доки 1/3] [📥 Экспорт]
```

- ✅ = завершено
- 6/10 = прогресс
- 1/3 = частично готово
- Без иконки = не начато

## 8. Micro-UX паттерны

### 8.1 Автосохранение в редакторе

```
Пользователь редактирует документ
    │
    ├── Каждые 30 секунд → PUT /generated/{id}
    │
    ├── Индикатор: "Сохранено только что" (top-right угол редактора)
    │
    └── При закрытии без сохранения:
        "Есть несохранённые изменения. Сохранить?"
        [Сохранить] [Выйти без сохранения] [Отмена]
```

### 8.2 Оптимистичные обновления

```
Пользователь меняет статус проекта:
1. Status Badge обновляется МГНОВЕННО (optimistic)
2. PUT /projects/{id} отправляется в фоне
3. При ошибке → откат к предыдущему статусу + Toast
```

### 8.3 Скелетон при загрузке

```
При переходе на страницу анализа → показывается skeleton:
┌──────────────────────────────────┐
│ ███████████████ █████████        │
│ ████████████ ████████████████   │
│                                  │
│ ██████ █████████████             │
│ ████████ ██████ █████████████   │
└──────────────────────────────────┘
```

### 8.4 Hover tooltips

Для сокращённых текстов и иконок:
- Hover на Risk Badge → полное описание риска
- Hover на краткое требование → полный текст
- Hover на иконку источника → «Раздел 3.2, стр. 12»

### 8.5 Прогрессивное раскрытие

```
AnalysisPanel — список требований (47 штук):
- Показываем первые 5 по умолчанию
- [Показать все 47 →]
- При клике — анимированное раскрытие
```

## 9. Ключевые UX-метрики

| Метрика | Цель | Способ измерения |
|---------|------|-----------------|
| Time to first project (TTFP) | < 3 мин | Аналитика (Mixpanel) |
| Time to first analysis | < 5 мин с момента загрузки ТЗ | Аналитика |
| Time to first export | < 10 мин с момента загрузки | Аналитика |
| Chat completion rate | > 80% | Процент сессий с is_complete=true |
| Generation success rate | > 95% | Процент успешных задач |
| User rating (👍) | > 75% | Процент 👍 из total ratings |
| Session depth | > 3 pages/session | GA4 |

## 10. Accessibility UX Flow

```
Клавиатурная навигация:
    Tab → переход между интерактивными элементами
    Enter/Space → активация кнопок
    Escape → закрытие модалов, dropdown
    Arrow keys → навигация по спискам, dropdown

Screen reader:
    ARIA labels на всех кнопках
    Live regions для динамических обновлений (анализ, генерация)
    Semantic headings (h1 → h2 → h3)
    Alt text для всех изображений

Motion preferences:
    При prefers-reduced-motion:
    - Отключены все CSS transitions
    - Skeleton без shimmer
    - Progress bar без shimmer
```
