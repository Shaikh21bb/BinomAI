## 1. Executive Summary

BINOM AI — это Enterprise SaaS-платформа с AI Copilot для автоматизации подготовки тендерной документации строительными компаниями Казахстана.

Продукт решает критическую бизнес-проблему: подготовка тендерного пакета занимает 3–10 рабочих дней, требует высокой экспертизы и подвержена ошибкам, которые ведут к дисквалификации.

**BINOM AI сокращает это время до 2–4 часов** за счёт AI-анализа технического задания, автоматической генерации документов и интерактивного сопровождения пользователя.

### Ключевые факты

| Параметр | Значение |
|----------|----------|
| **Тип продукта** | Enterprise SaaS + AI Copilot |
| **Модель монетизации** | Subscription (SaaS) |
| **MVP срок** | 6 недель (3 спринта по 2 недели) |
| **Целевой рынок** | Казахстан, строительство |
| **Основной язык** | Русский |
| **Frontend** | Зафиксирован, изменению не подлежит |
| **AI-движок** | Gemini 1.5 Pro + GPT-4o (fallback) |

## 4. Постановка проблемы

### 4.1 Описание проблемы

Тендерные специалисты строительных компаний Казахстана сталкиваются с системной проблемой: **технические задания содержат от 30 до 300+ страниц плотного технического текста**, требования неструктурированы, а сроки подачи — жёсткие.

Текущий процесс:

```
Получение ТЗ → Ручное чтение (4–16ч) → Выявление требований (2–8ч) 
→ Подготовка КП (8–24ч) → Подготовка тех. части (8–24ч) 
→ Проверка (4–8ч) → Сборка пакета (2–4ч) → Подача
```

**Итого: 28–84 часа на один тендер**

### 4.2 Экономический ущерб

Для компании, участвующей в 20 тендерах в год:
- Прямые затраты на специалистов: 1 400 000 – 4 200 000 тг/год
- Потерянные тендеры из-за ошибок: 5–15% от поданных
- Упущенная выручка из-за ограниченного числа тендеров: неограничена

### 4.3 Формулировка проблемы

> *«Тендерные специалисты строительных компаний Казахстана не могут масштабировать участие в тендерах и часто допускают ошибки, потому что процесс анализа ТЗ и подготовки документации полностью ручной, не стандартизированный и крайне трудоёмкий.»*

## 6. Пользовательские сценарии (User Journey)

### 6.1 Основной сценарий (Happy Path)

```
Шаг 1: Регистрация и онбординг
Пользователь регистрируется → заполняет профиль компании 
→ загружает шаблоны и стандарты компании

Шаг 2: Создание нового проекта
Пользователь нажимает «Новый тендер» → вводит название 
→ загружает PDF/DOCX с ТЗ

Шаг 3: AI-анализ
Система автоматически парсит документ → AI анализирует ТЗ 
→ отображает структурированные результаты:
  • Извлечённые требования
  • Выявленные риски
  • Gap-анализ (что отсутствует)
  • Предварительная оценка сложности

Шаг 4: Уточняющий диалог
AI задаёт вопросы пользователю для уточнения деталей
Пользователь отвечает → AI обновляет контекст

Шаг 5: Генерация документов
Пользователь выбирает нужные документы → нажимает «Сгенерировать»
AI создаёт:
  • Коммерческое предложение
  • Техническую спецификацию  
  • Сопроводительное письмо

Шаг 6: Редактирование
Пользователь просматривает документы в редакторе
Вносит правки при необходимости

Шаг 7: Экспорт
Пользователь нажимает «Экспортировать» → выбирает DOCX / PDF
Скачивает готовый тендерный пакет
```

### 6.2 Альтернативные сценарии

**Сценарий B: Недостаточно данных в ТЗ**
- AI выявляет критические пробелы
- Создаёт список вопросов для заказчика
- Генерирует частичные документы с плейсхолдерами

**Сценарий C: Повторный тендер**
- Пользователь копирует предыдущий проект
- AI адаптирует документы под новые требования

**Сценарий D: Высокий риск тендера**
- AI выявляет критические риски
- Предупреждает пользователя
- Предлагает варианты митигации в тексте КП

## 9. MVP Scope

### 9.1 В объём MVP входит

✅ Аутентификация (email/password)  
✅ Профиль пользователя и компании  
✅ Создание и управление проектами  
✅ Загрузка PDF и DOCX  
✅ AI-анализ ТЗ (требования, риски, gaps)  
✅ Интерактивный AI-чат  
✅ Генерация Коммерческого предложения  
✅ Генерация Технической спецификации  
✅ Генерация Сопроводительного письма  
✅ Базовый редактор документов  
✅ Экспорт DOCX  
✅ Экспорт PDF  

### 9.2 Не входит в MVP

❌ Казахский язык  
❌ SSO (Google / Microsoft)  
❌ Multi-user (приглашение коллег)  
❌ Биллинг и управление подпиской  
❌ Кастомные шаблоны  
❌ Интеграция с goszakup.gov.kz  
❌ OCR для сканов  
❌ Мобильное приложение  

### 9.3 Definition of Done для MVP

MVP считается готовым к релизу, когда:
- Все Must Have функции реализованы и протестированы
- AI-анализ возвращает релевантные результаты на реальных ТЗ
- Экспорт DOCX/PDF работает корректно
- Нет критических багов (severity P1/P2)
- Uptime в тестовой среде > 99% за 7 дней
- Хотя бы 2 пользователя из целевой аудитории прошли User Testing и оценили опыт > 4/5

## 11. Acceptance Criteria (Критерии приёмки)

### AC-1: Загрузка документа

```
GIVEN пользователь авторизован и находится в проекте
WHEN он нажимает «Загрузить ТЗ» и выбирает PDF-файл до 50 МБ
THEN файл загружается за < 10 секунд
AND отображается индикатор прогресса
AND файл виден в интерфейсе после загрузки
AND система начинает AI-анализ автоматически
```

### AC-2: AI-анализ ТЗ

```
GIVEN ТЗ загружено и обработано
WHEN AI завершает анализ (< 30 секунд)
THEN на экране отображается:
  - Список технических требований (не менее 80% от реально присутствующих)
  - Список рисков (если есть)
  - Gap-анализ (если есть)
  - Краткое резюме ТЗ
AND все данные кликабельны и ссылаются на исходный текст
```

### AC-3: AI-чат

```
GIVEN анализ ТЗ завершён
WHEN пользователь открывает чат
THEN AI автоматически задаёт первый уточняющий вопрос
AND вопрос релевантен содержанию загруженного ТЗ
WHEN пользователь отвечает на вопрос
THEN AI задаёт следующий вопрос или подтверждает достаточность информации
AND история диалога сохраняется
```

### AC-4: Генерация Коммерческого предложения

```
GIVEN AI-анализ и диалог завершены
WHEN пользователь нажимает «Сгенерировать КП»
THEN документ генерируется за < 60 секунд
AND документ содержит все обязательные разделы КП
AND текст релевантен требованиям загруженного ТЗ
AND документ доступен для редактирования в онлайн-редакторе
```

### AC-5: Экспорт DOCX

```
GIVEN документ сгенерирован (и при необходимости отредактирован)
WHEN пользователь нажимает «Скачать DOCX»
THEN файл .docx скачивается за < 10 секунд
AND файл открывается в Microsoft Word без ошибок
AND форматирование соответствует корпоративному стандарту
AND в документе присутствует логотип компании (если загружен)
```

### AC-6: Экспорт PDF

```
GIVEN документ сгенерирован
WHEN пользователь нажимает «Скачать PDF»
THEN файл .pdf скачивается за < 10 секунд
AND PDF содержит корректный текст (не изображения)
AND форматирование соответствует DOCX-версии
```

## 13. Риски и допущения

### 13.1 Риски

| ID | Риск | Вероятность | Влияние | Митигация |
|----|------|-------------|---------|-----------|
| R1 | Качество AI ниже ожидаемого на реальных ТЗ | Высокая | Критическое | Итеративный промпт-инжиниринг, тест на 50 реальных ТЗ |

| R4 | Резкий рост стоимости AI API | Средняя | Высокое | Оптимизация токенов, кэширование, rate limits |
| R5 | Сложности с парсингом сложных PDF (таблицы, схемы) | Высокая | Среднее | LlamaParse, специализированные парсеры |
| R6 | Низкая конверсия из регистраций в платящих | Средняя | Высокое | Freemium модель, активный онбординг |
| R7 | Корпоративные требования к хранению данных в РК | Средняя | Высокое | Хостинг в дата-центре в Казахстане |

### 13.2 Допущения

- Frontend уже разработан и не требует изменений
- Пользователи имеют базовый уровень компьютерной грамотности
- ТЗ предоставляются в машиночитаемом формате (не сканы без OCR в MVP)
- Доступ к API Gemini 1.5 Pro обеспечен
- Supabase подходит для MVP без необходимости кастомной инфраструктуры БД
- Казахстанское законодательство о персональных данных не требует on-premise решения для MVP

## 14. AI-требования (AI Requirements)

### 14.1 Требования к AI-анализу

| Требование | Описание |
|-----------|----------|
| AI-ML-01 | Модель должна понимать технические термины строительной отрасли |
| AI-ML-02 | AI должен различать типы тендеров: EPC, поставка, услуги, строительство |
| AI-ML-03 | AI должен извлекать структурированные данные (списки, таблицы) из неструктурированного текста |
| AI-ML-04 | AI должен определять категорию тендера по контексту |
| AI-ML-05 | AI должен генерировать тексты в профессиональном деловом стиле (русский язык) |
| AI-ML-06 | AI должен учитывать контекст предыдущих ответов пользователя при генерации |
| AI-ML-07 | AI не должен «галлюцинировать» факты — только использовать информацию из ТЗ и ответов |

### 14.2 Промпт-стратегия

Детальная стратегия описана в [Prompt Library.md](../04_AI/Prompt%20Library.md).

Ключевые принципы:
- System prompt с ролью: «Ты — AI-ассистент для подготовки тендерной документации»
- Structured output (JSON) для всех AI-запросов, кроме чата
- Chain-of-thought для сложных аналитических задач
- Few-shot примеры для генерации документов
- Temperature: 0.2–0.4 для анализа, 0.6–0.7 для генерации

### 14.3 Оценка качества AI

| Метод | Описание |
|-------|----------|
| Human evaluation | Экспертная оценка на 50 реальных ТЗ до запуска |
| A/B тестирование промптов | Сравнение версий промптов по качеству |
| User feedback | CSAT-оценка после каждой генерации |
| Automated metrics | BLEU, ROUGE для текстовой генерации |
| Error tracking | Логирование всех ошибок AI и их причин |
