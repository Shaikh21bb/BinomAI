## 2. Static Knowledge — Строительная отрасль

### 2.1 Типы тендеров

Встроено в Master System Prompt для корректной классификации:

```
ТИПЫ ТЕНДЕРОВ:

1. EPC (Engineering-Procurement-Construction)
   Полный цикл: проектирование + поставка + строительство
   Ключевые особенности:
   - Единый подрядчик несёт полную ответственность
   - Контракт "под ключ" (lump sum turnkey)
   - Высокие требования к квалификации
   - Обязательна банковская гарантия
   Примеры объектов: НПЗ, химзаводы, электростанции

2. Строительный подряд (Construction)
   Только строительно-монтажные работы по готовому проекту
   Ключевые особенности:
   - Проектная документация предоставляется заказчиком
   - Ответственность за соблюдение проекта
   - Гарантия на СМР
   Примеры: жилые дома, офисные здания, дороги

3. Поставка (Supply)
   Закупка оборудования, материалов, товаров
   Ключевые особенности:
   - Спецификация в ТЗ или приложении
   - Требования к сертификатам продукции
   - Условия доставки (Инкотермс)
   - Гарантийный срок на оборудование

4. Услуги (Services)
   Инжиниринговые, консультационные, технические услуги
   Ключевые особенности:
   - Техническое задание на услуги
   - Квалификация специалистов
   - Методология выполнения

5. Смешанный (Mixed / Design-Build)
   Комбинация нескольких типов
   Определяется по составу работ в ТЗ
```

| Акт приёмки | Документ о сдаче работ | F3/Ф3, КС-11 |

## 7. RAG Vector Store (Phase 2)

### 7.1 Архитектура (планируемая)

```
Vector Store (pgvector в Supabase):

documents_kb таблица:
- id UUID
- category VARCHAR (нормы / глоссарий / примеры / шаблоны)
- title TEXT
- content TEXT
- embedding VECTOR(1536)  -- OpenAI ada-002 embeddings
- metadata JSONB
- language VARCHAR
```

### 7.2 Запланированный контент для векторизации

| Категория | Источник | Приоритет | Объём |
|-----------|---------|-----------|-------|
| СН РК | Официальный сайт МИИР | High | 50 документов |
| ГОСТ (строительство) | Росстандарт (применяется в РК) | High | 100 документов |
| Образцы ТЗ | Goszakup архив | Medium | 200 документов |
| Образцы КП | Внутренние + партнёры | High | 50 документов |
| Судебная практика | Поиск по коммерческим спорам | Low | 20 документов |
| Глоссарий | Составной | High | 1 документ |

### 7.3 RAG Pipeline (Phase 2 план)

```python
class RAGLayer:
    """Phase 2: RAG для нормативной базы"""
    
    async def retrieve_norms_for_requirements(
        self,
        requirements: List[str],
        tender_type: str,
        top_k: int = 5
    ) -> List[RelevantNorm]:
        
        # Создаём embedding запроса
        query = " ".join(requirements[:10])  # Топ-10 требований
        embedding = await self.embed(query)
        
        # Поиск в pgvector
        norms = await self.db.execute("""
            SELECT title, content, metadata
            FROM documents_kb
            WHERE category = 'norms'
              AND metadata->>'tender_type' = $1
            ORDER BY embedding <-> $2::vector
            LIMIT $3
        """, tender_type, embedding, top_k)
        
        return [RelevantNorm(
            title=n["title"],
            relevant_text=n["content"][:500],
            citation=n["metadata"]["citation"]
        ) for n in norms]
```

## 8. Контроль качества Knowledge Base

### 8.1 Процесс обновления KB

```
Обновление Static Knowledge:
1. AI Engineer + Domain Expert проверяют промпты
2. Тестирование на 10 реальных ТЗ
3. Сравнение качества (до/после)
4. Деплой новой версии промптов

Обновление Templates:
1. Юрист / эксперт проверяет шаблон
2. PM утверждает структуру
3. AI Engineer интегрирует в промпты
4. QA тестирует генерацию

Цикл обновления: ежемесячно или при обнаружении ошибок
```

### 8.2 Метрики качества KB

| Метрика | Описание | Цель |
|---------|----------|------|
| Domain Accuracy | % корректных технических терминов | > 95% |
| Norm Relevance | % релевантных норм в ТС | > 80% |
| Template Adoption | Соответствие шаблону структуры | > 90% |
| Expert Rating | Оценка эксперта-строителя | > 4/5 |

## 9. Ограничения Knowledge Base (MVP)

| Ограничение | Описание | Планируемое решение |
|-------------|----------|---------------------|
| Нет полной базы норм | В MVP только ключевые нормы | Phase 2: RAG со всеми СН РК |
| Нет реальных ТЗ-прецедентов | KB основана на общей экспертизе | Phase 2: обучение на реальных кейсах |
| Только русский язык | Нет казахского | Phase 3: двуязычность |
| Нет ценовых баз | Нет данных о рыночных ценах | Phase 4: интеграция со сметными базами |
| Общие нормы без специализации | Нет глубокой отраслевой специализации | Phase 3: вертикали (нефть, дороги, жильё) |
